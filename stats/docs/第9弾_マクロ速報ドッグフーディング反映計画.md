版: 2026-08-29／分類: **設計**（着手判断が出たら実施記録をデータ拡充計画 §4d へ）。
要件源＝2026-08-28〜29 の開発者自身の利用セッション（claude.ai から開発用の stats コネクタ経由・GDP に関する資料作成の問答 3 問）。§1 はそのときの評価の要約。

## 1. 要件源（利用評価の要約）

### 効いた点
1. 実質・名目 GDP の 1994 年以降の四半期系列を lookup_panel 1 回で取れ、過去比較（平均・中央値・標準偏差、局面別 CAGR）を最初の一手で出せた。
2. 出典テンプレート・vintage・ライセンスが値に付くので、資料に載せる際の出所表記を考えずに済んだ。
3. find_statistics で scope=jp が 0 件のとき「絞り込みを外すと 1 件ある」というヒントが返り、「収録なし」との誤認を避けられた。

### 足りなかった点
1. 収録が 2026 年 1-3 月期 2 次速報まで。本題の 4-6 月期 1 次速報（8/17 公表）は原典から直接取る必要があった＝1 次 QE 公表当日〜翌日の取込が無いと、足元の議論では毎回外に出ることになる。
2. QE のデフレーター系列が無い（SNA 年次の GDP デフレーターのみ）。前期比・前年比・寄与度・デフレーターの各表の系列化が要る。
3. 潜在成長率・需給ギャップ（日銀・内閣府）が入っていない、と利用側は認識した（§2 #3 で検証）。
4. 検索語の癖。「実質GDP」で 0 件、「GDP」だと 77 件。日本語の複合語で当たるようにするか、hint で再検索語を示してほしい。

### 総括
3 問のうち、過去比較はコネクタで完結、4-6 月期の中身と潜在成長率は外部、デフレーター分解は半々。「歴史データの土台」としては機能しており、「足元の速報」と「加工統計（ギャップ・デフレーター・寄与度）」が入れば、この種の質問はほぼコネクタ内で閉じる。

## 2. 実測検証（2026-08-29・ローカル registry 9,438 系列で確認）

指摘を鵜呑みにせず登録・値・検索の実物で確かめた。**1 件は半分誤認＝それ自体が最重要の発見**。

| # | 指摘 | 判定 | 実測 |
|---|---|---|---|
| 1 | 4-6 月期 1 次速報が未収録 | **正** | `cao.qe2020.gdp_real.sa.q` の最終値＝2026Q1・vintage 2026-06-07（1-3 月期 2 次）・retrieved 2026-08-17。**accessor の file が `sokuhou/files/2026/qe261_2/...` と edition 固定**＝再取込しても新しい期は永久に入らない構造。速報性は運用の問題ではなく seed の設計問題 |
| 2 | QE デフレーターが無い | **正** | デフレーターは `cao.sna2020.deflator.{fy,a}`（年次）と `sna_activity` の 3 種（活動別・暦年）のみ。QE 需要項目別デフレーター・寄与度は未収録 |
| 3 | 潜在成長率・需給ギャップが入っていない | **半分誤認** | 日銀 `boj.gap` 8 系列は**収録済**（需給ギャップ 2026Q1・潜在成長率 FY2025H2 まで・vintage 2026-07-01）。「潜在成長率」「需給ギャップ」の単語で 16 件／8 件当たる。**未収録は内閣府版 GDPギャップ・潜在成長率のみ**。ただし検索語「GDPギャップ」（内閣府の呼称）は **0 件**＝#4 と同根＋別名不足。**収録済みの系列が利用側に「無い」と報告された**＝発見層か tool-choice の欠陥であり、取込より先に原因を確定する |
| 4 | 「実質GDP」0 件・「GDP」77 件 | **正・原因確定** | `Registry.tokenize` が空白区切りのみ＝「実質GDP」「GDPギャップ」「実質GDP 四半期」は単一トークンの部分一致に失敗し 0 件。「GDP 実質」と空白を入れれば 23 件。**英字と和字が融合した複合語**（実質GDP・名目GDP・GDPギャップ・GDPデフレーター…）が全滅する系統的欠陥 |

効いた点 3 件はいずれも過去弾の成果の実証（B11 lookup_panel・出典テンプレート＝A-4・S-1 の 0 件診断）＝**回帰で守る側**。特に 3 は「hint が無ければ誤認していた」との証言＝0 件診断の投資が実際に誤答を止めた記録として残す。

## 3. 計画（段 0〜4・推奨順）

完了条件は全弾共通：seed→取込→別経路照合の exact_match 追加→ゲート 3 本 PASS→docs 更新。**取込後は HTTP(:8766) の上げ直し**（第 7 弾補遺 3 の地雷）と箱への反映を忘れない。

### 段 0 誤認経路の確定（調査・0.5 セッション）

- 開発用サーバ（stats-dev）の捕捉ログ `query_log/queries.jsonl` から当該セッション（2026-08-28〜29）の検索語・found=false を抽出し、指摘 3 の経路を確定する：
  (a) 「GDPギャップ」等で検索して 0 件だった（発見層の欠陥＝段 1 で直る）のか、
  (b) そもそも stats を呼ばず Web に出た（tool-choice＝ChatGPT コネクタ知見と同型。★バイパスはログに残らないので「該当検索が無い」ことが (b) の証拠になる）のか。
- (b) なら対処は SERVER_INSTRUCTIONS／ツール説明文の側（「潜在成長率・需給ギャップは収録済み」を発見層に届く語彙で書く）＝モデル非依存で。

### 段 1 発見層の複合語対応（1 セッション・最安・即効）

- `Registry.tokenize` に**文字種境界の分割**を追加：ASCII 英数字 ↔ 漢字・かな・カナの境目で切る（「実質GDP」→［実質, GDP］の AND・「GDPギャップ」→［GDP, ギャップ］）。決定論・辞書不要。S-1（複数語 AND）と同じ層の小改造。
- 別名の補強：`boj.gap.output_gap` の notes に「GDPギャップ（内閣府の呼称）」、潜在成長率系列に「成長力」等、呼称の官庁差を吸収する語を置く（段 4 の内閣府版を入れたら相互参照）。
- 0 件 hint の強化：分割後も 0 件のとき「複合語を分割して再検索した結果 N 件」を matched_tokens に含める（利用者要望の「hint で再検索まで示す」の実装）。
- ガード＝`find_golden.jsonl` 20 語の must_keep 不変＋smoke。ゴールデンに「実質GDP」「GDPギャップ」「名目GDP」を追加。

### 段 2 QE デフレーター・寄与度の収録（1〜2 セッション）

- `qe2020` に追加（すべて**公表値のまま**＝寄与度・前期比の自前計算は入れない。近似禁止の原則に適合）：
  (a) 需要項目別デフレーター 季節調整指数（rdef-jk 系 CSV・9 項目）、
  (b) 同 前期比・前年同期比（rdef-qk 系＝ログで利用者が生読みした表）、
  (c) 実質成長率への需要項目別寄与度（kiyo 系 CSV・内需/外需・項目別）。
- 規模感＝9 項目 ×（水準・前期比・前年比）＋寄与度 ≒ 35〜40 系列。既存 `esri_qe_csv` の系譜＝新 accessor 不要の見込み（列見出しの確認のみ）。
- これでログの「rdef-qk を生で読んで名目ウエイトを自前計算」の往復が消える。名目シェアも既存 `*_nominal.sa.q` から出せる旨を analysis_notes へ。

### 段 3 速報性＝QE 更新運用（2〜3 セッション・本丸）

指摘 1 の恒久対処。横断 (b)「月次バッチ・vintage 更新」の定常化を、**改定頻度が最も高く需要が実証された QE を先行事例**として設計する。

- (a) **edition 自動発見**：seed の固定 URL をやめ、ESRI 統計表一覧ページ（または `sokuhou/files/{年}/qe{YY}{Q}_{1|2}/` の命名規則）から最新 edition を決定論で解決する。発見した edition は accessor に刻む（現行どおり原本追跡可能に）。
- (b) **公表カレンダー連動**：QE は年 8 回（1 次・2 次）・公表日は事前公表＝公表日翌日までに再取込する運用（当面は手動キック・ゲート付き。timer 化は箱の refresh 運用と同時）。
- (c) **改定の扱い**：最新 vintage のみ保持（WEO と同じ②判断 5）。QE は改定で**過去値が全期間動く**＝exact_match 正例の期待値が Fail する。再取込時の規則を評価設計に追加：正例の期待値は「最新 vintage の原典と一致」で更新し、更新の事実を記録（黙って書き換えない）。
- (d) 反映の締め＝ローカル HTTP 上げ直し＋箱への同期（tar 再展開＝bootstrap 再走行では反映されない・★staging 再建の地雷）。
- 効果測定＝次回 QE（7-9 月期 1 次速報・11 月公表）で「公表翌日にコネクタから引けた」を確認して完了とする。

### 段 4 内閣府版 GDPギャップ・潜在成長率（1 セッション）

- 原典＝内閣府の四半期推計（「月例経済報告関連 GDPギャップ、潜在成長率」Excel）。日銀版（収録済）と**推計手法・水準が違う別系列**＝混ぜない。dims か dataset で `cao` を分け、notes に定義差（生産関数の仕様・改定頻度）を明記。
- `gap.analysis_notes`（第 8 弾第 1 便）に「日銀版と内閣府版の並べ方」（両方を並記し推計主体を明示・水準差は推計差であって誤りではない）を追記。
- 段 0 の結果が (b)（tool-choice）だった場合も、内閣府版の追加は「GDPギャップ」の表題一致を生むので発見層の防御を兼ねる。

## 4. 判断が要る点（選択肢と推奨）

1. **順序**：(a) 0→1→2→3→4（推奨：調査と最安対処を先に。段 3 は次回 QE 公表＝11 月が効果測定の自然な締切なので急がず設計を固める）／(b) 2 を先に（デフレーター需要が再来する見込みなら）。
2. **段 3 の自動化の程度**：(a) 手動キック＋手順書（推奨：ゲートを人が見る現行運用と整合）／(b) systemd timer で全自動（箱の refresh 定常化と同時期に）。
3. **段 2 の範囲**：(a) デフレーター 3 種＋寄与度まで（推奨：ログの往復を全部消す）／(b) デフレーター水準のみ先行。
4. **雇用者報酬・GDI**：ログの結び「実質所得（GDI）ベースでは成長率がさらに低い」は QE の実質雇用者報酬・交易利得表で裏が取れる。段 2 に含めるか（+数系列）は要望が再来してから（推奨＝今回は見送り・記録のみ）。

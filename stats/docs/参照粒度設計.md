# 参照粒度設計 — series_id・period・地域・単位・改定・出典の刻み方・評価セット

> **状態：設計（安定リファレンス・起案時の判断。現行の実装名・数値は stats/README とルート README）。**

版: 2026-08-16（D3 最初の一手③）／入力: `指標棚卸し.md`（S/A 系列）・`データソース選定.md`（取得元・アクセサ・確定 statsDataId）。
出力: 参照層が返す「1つの値」の**同定方法**（何を・いつの・どこの・どの版の値か）と、それを刻む器（`core/registry.py` の `Series` 拡張）、原典完全一致の評価セット（`stats/data/eval/`）の形。実装は D3 の次段（`stats.ingest`）。

設計の芯：**値は原典の表のセルそのもの**。こちらで換算・丸め・季調・接続・派生計算をしない。したがって「1つの値」＝（系列 × 期間 × 地域 × 版）で一意に定まり、出典は**そのセルに戻れる粒度**で刻む。

## 1. series_id の命名規則

```
<org>.<dataset>.<measure>[.<dims>].<freq>[.<region_level>]
```

| 部分 | 規則 | 例 |
|---|---|---|
| `org` | 公表主体コード（小文字 ASCII・固定語彙） | `cao`（内閣府）`mof`（財務省）`boj`（日銀）`soumu`（総務省）`mhlw`（厚労省）`meti`（経産省）`nta`（国税庁）`ipss`（社人研）`jpx`／`imf` `oecd` `wb`／`keidanren` `rengo` |
| `dataset` | 統計名の略号。**基準年・体系で値が変わる統計は基準年を含める**（＝別 series） | `sna2020`（2020年基準・2008SNA 年次推計）`qe2020`（QE）`cpi2020`／`cpi2025`／`hojin`（法人企業統計 時系列）`roudou`（労働力調査）`maikin`（毎勤 長期時系列）`jinko`（人口推計）`gap`（需給ギャップ・潜在成長率）`tankan` `fof`（資金循環）`bop`（国際収支）`fx` `jgb`（国債金利）`zaisei`（財政統計）`kokusai`（国債統計）`weo` `fm` `wdi` `pdb`／`shunto`（春季妥結） |
| `measure` | 指標の略号（英小文字＋数字・`_`） | `gdp_nominal` `gdp_real` `deflator` `hh_consumption` `priv_capex` `sales` `operating_profit` `cash_deposits` `retained_earnings` `wage_total_nominal` `wage_total_real` `cpi_all` `cpi_ex_fresh` `cpi_ex_fresh_energy` `unemployment_rate` `employed` `pop_total` `pop_15_64` `potential_growth` `output_gap` `jgb10y` `debt_gdp` |
| `dims` | 内訳（省略可・`key-value` を `-` で連結・語彙は dataset ごとに固定） | 法企：`allexfin-allsize`（全産業除く金融保険・全規模）／毎勤：`total-5plus`（就業形態計・5人以上）`fulltime-5plus`／労調：`total`・`m`・`f`・`age15_64`／短観：`large-mfg`／SNA：`sa`（季調系列）`nsa` |
| `freq` | 期間粒度コード | `a`（暦年）`fy`（年度）`h`（半期）`q`（四半期・暦年ベース）`fq`（四半期・年度ベース）`m`（月次）`d`（日次）`irr`（不定期・調査年） |
| `region_level` | 地域粒度（全国のみの系列は省略） | `pref`（都道府県）`city`／国際：`cty`（国別） |

例：
- `cao.sna2020.gdp_nominal.fy` ／ `cao.qe2020.gdp_real.sa.q` ／ `cao.sna2020.net_lending.hh.a`
- `mof.hojin.sales.allexfin-allsize.fy` ／ `mof.hojin.cash_deposits.allexfin-allsize.fq`
- `soumu.cpi2020.cpi_ex_fresh.m` ／ `soumu.cpi2025.cpi_ex_fresh.m`（別系列）／ `soumu.roudou.unemployment_rate.total.m` ／ `soumu.roudou.employed.total.a.pref`
- `mhlw.maikin.wage_total_real.total-5plus.m` ／ `mhlw.shokugyo.job_openings_ratio.m`
- `boj.gap.potential_growth.h` ／ `boj.gap.output_gap.q` ／ `boj.tankan.bsi.large-mfg.q` ／ `boj.fx.usdjpy_avg.m`
- `mof.jgb.yield.10y.d` ／ `mof.zaisei.expenditure_general.social_security.initial.fy`（当初）／`…revised.fy`（補正後）／`…settled.fy`（決算）
- `ipss.pop2023.pop_total.medium-medium.a`（`kind=projection`）／ `imf.weo.gdp_real_growth.a.cty`（WEO は最新版のみ保持＝②判断5。版名は値の `vintage`／系列の `edition` に刻む。版ごとに系列を分ける場合のみ dataset に版を入れる）
- `keidanren.shunto.wage_hike_rate.large.a` ／ `keidanren.shunto.wage_hike_rate.sme.a`

規則：一度公開した series_id は変えない。定義変更・基準改定・季調替えで値が変わる場合は**新 series_id**（旧は `superseded_by` を刻んで残す）。派生値（比率・前年比・GDP比・接続系列）は series を作らず、`components`（構成系列の series_id 群）を持つ**仮想エントリ**として発見層にだけ載せる（§6）。

## 2. period 表記

| 粒度 | 表記 | 意味 | 内部正規化（`period_start`/`period_end`） |
|---|---|---|---|
| 暦年 | `2024` | 2024年1–12月 | 2024-01-01／2024-12-31 |
| 年度 | `FY2024` | 2024年4月–2025年3月 | 2024-04-01／2025-03-31 |
| 暦年四半期 | `2024Q1` | 1–3月 | 2024-01-01／2024-03-31 |
| 年度四半期 | `FY2024Q1` | 4–6月（法企・SNA 年度ベース四半期はこれ） | 2024-04-01／2024-06-30 |
| 半期（年度） | `FY2024H1`／`FY2024H2` | 4–9月／10–3月（日銀 gap） | — |
| 月 | `2024-03` | — | 2024-03-01／2024-03-31 |
| 日 | `2024-03-31` | 基準日（金利・為替） | — |
| 時点 | `2024-03-31E`（末残） | ストック（残高・人口 10月1日は `2024-10-01`） | — |
| 調査年（不定期） | `2021`（調査年）＋ `survey_ref` に対象年 | 所得再分配調査等 | — |

- 利用者入力は上記表記に**厳密一致**させる（`2024` を年度系列に投げたら found=false・「この系列は FY 表記」を `hint` で返す＝近似しない）。
- e-Stat 時間コード（`19600`＝1960年度・`2026000707`＝2026年7月・`2025100000`＝2025年度 等）や ESRI xlsx の列見出しは取込時に上記へ**決定論で変換**し、変換表を dataset ごとに `stats/core/periods.py` に固定する（テスト対象）。
- 「基準年」（2015年価格・2020年基準）は period ではなく series（dataset）に属する。

## 3. 地域

- 全国のみの系列：`region` は常に `JP`（既定）。都道府県：JIS X 0401 2桁（`13` 東京都）。CPI の「全国」`00000`／「東京都区部」等は e-Stat の area コードを `region_code_source` に保持し、正規化は `JP` と都道府県コードだけ（市・地方ブロックは最小版外）。
- 国際：ISO 3166-1 alpha-3（`JPN` `USA` …）。
- lookup で系列に無い地域を指定されたら found=false（`reason=region_not_available`）。

## 4. 単位・値の表現

- `value` は**公表どおりの文字列**（例 `"599948.4"`・`"2.8"`・`"-0.3"`）を保持し、数値変換は利用者側。丸め・単位換算をしない。単位は series の `unit`（`10億円`・`百万円`・`％`・`万人`・`指数（2020年=100）`・`人`）を公表どおり。
- 欠測・秘匿・該当なし（`-`・`…`・`x`）は値ではなく **found=false（reason=`suppressed`／`not_published`）**。
- 速報・改定・確報の区別は `status`（`p` 速報／`r` 改定／`f` 確報／`` 通常）を公表記号から刻む。

## 5. 改定（版）の扱い

| 種類 | 扱い |
|---|---|
| **基準改定**（SNA 2015→2020 基準、CPI 2020→2025 基準、鉱工業 2020 基準） | **別 series**（dataset に基準年）。旧系列は残し `superseded_by` を刻む。接続指数（総務省公表）は独立の series（`soumu.cpi_link.…`）としてのみ持つ |
| **定期改定**（QE 2次速報・年次推計での遡及、法企の年報確定、毎勤の確報、WEO の版） | 同一 series の**版（vintage）**。各値に `vintage`（公表日 or 取得ファイルの版名）を持ち、参照層は**最新版**を返す。旧版は cache 原本にのみ残す（版指定の参照は最小版外） |
| 季節調整替え | 季調系列は原系列と別 series（`sa`）。季調替えは vintage 更新として扱う |
| 推計・見通し | `kind=projection`。`projection_by`・`edition`（例 `令和5年推計`／`WEO 2026年4月`／`中長期試算 2026年1月`）・`scenario`（`出生中位死亡中位`／`成長移行ケース`）を必須。観測値と同じ lookup で返るが、返り値に `kind` を明示し、説明文でも「推計値」を先頭に置く |

## 6. 出典の刻み方（機械可読＋人が読む1行）

lookup の返り値 `source` は必ず次を持つ（要件源の「データの出所」行の前例＝統計名・調査主体・表・基準年・取得日を踏襲し、機械可読にする）：

```json
{
  "org": "mof", "org_name": "財務省",
  "stat_name": "法人企業統計調査 時系列データ",
  "table_id": "0003060791", "table_title": "金融業、保険業以外の業種（原数値）年度次",
  "basis": null,
  "accessor": {"type": "estat", "statsDataId": "0003060791", "cdCat01": "002", "cdCat02": "104", "cdCat03": "26", "cdTime": "20240"},
  "url": "https://www.e-stat.go.jp/dbview?sid=0003060791",
  "published_at": "2025-09-01", "vintage": "2025-09-01", "retrieved_at": "2026-08-16",
  "citation": "財務省「法人企業統計調査 時系列データ」金融業、保険業以外の業種（原数値）年度次（e-Stat 0003060791・現金・預金／全産業（除く金融保険業）／全規模／2024年度）取得 2026-08-16"
}
```

`accessor.type` の語彙：`estat`（API パラメータ）／`esri_xlsx`（`file`・`sheet`・`row_label`・`col_label`）／`boj_ts`（`code`）／`boj_file`（`file`・`sheet`・`row`・`col`）／`mof_csv`／`mof_xlsx`／`imf_dm`（`indicator`・`iso3`・`edition`）／`oecd_sdmx`（`dataflow`・`key`）／`wb_api`（`indicator`・`iso2`）／`pdf_table`（`doc_id`・`page`・`table`・`row_label`・`col_label`）。**このアクセサだけで原典の同じセルに戻れる**ことが条件（評価セットの `source_locator` と同型）。

## 7. `Series` の拡張（`core/registry.py`）

現行 8+8 欄に加える（既存欄は維持・共通コア 8 欄と `validate_payload` は不変）：

| 欄 | 型 | 内容 |
|---|---|---|
| `sector` | str | 部門ファセット：`マクロ／企業／家計・労働／物価・金融／財政／人口／対外・国際` |
| `kind` | str | `observation`（既定）／`projection` |

| `seasonal_adjustment` | bool | 季調系列か |
| `region_codes` | tuple[str] | 提供地域（`("JP",)`／都道府県 47／ISO3 群） |

| `stat_name` `table_id` `table_title` `org_name` | str | 出典の固定部分 |

| `superseded_by` `supersedes` | str | 改定の系譜 |
| `components` | tuple[str] | 派生（仮想）エントリの構成系列。参照層は値を持たず、lookup では `reason=derived_see_components` を返す |

| `license` | dict | 再配布・商用利用条件（`grade` ◎/○/△・`terms`・`url`・`note`。docs/再配布条件.md。取得経路で決める） |

`Registry` は JSON/YAML（`stats/data/registry/series.jsonl`）から読み込む形にし、`register()` で §1 の命名規則・語彙・`kind=projection` の必須欄を検証する。値の格納は `stats/data/values/<series_id>.jsonl`（1行＝{period, region, value, status, vintage, retrieved_at, accessor 具体値}）。大物は S3。

## 8. MCP 契約への反映（`serving/mcp_server.py`）

- `lookup_statistic(series_id, period, region="JP")`：found=true → `value unit period region kind status vintage source`／found=false → `reason ∈ {unknown_series, period_format, out_of_range, region_not_available, not_published, no_values, derived_see_components, guide_only}` と `hint`（正しい period 表記・提供範囲・構成系列）。**hint に値を含めない**。
- **`status=guide`（2026-08-18 追加）**：取得元の再配布条件（例：経団連＝商用は事前相談）により**値を保持しない**系列。発見層には出る（存在と所在を示す）が、lookup は period に関わらず `found=false, reason=guide_only` と `guide`（原典 URL・文書名・表・行・列・値の形・注意・代替統計・ライセンス）を返し、**値は利用側 AI が原典を読んで取得する**。stats はその値を保証しない（応答に明記）。値を持たないので完全一致ゲートの正例からは外れる（負例で guide_only を検証）。
- `find_statistics(query, tags, org, sector, kind, freq, limit)`：発見層。`sector` `kind` `freq` を追加。返す payload に `first_period/last_period/unit/basis/accessor.type` を含める（利用者 Claude が正しい lookup を組めるように）。
- `lookup_panel(period, series_ids?, id_pattern?, dims?, region?)`：参照層の**パネル版**＝複数系列×期間を 1 回で（2026-08-21 追加・残タスク B11。要件源＝シフトシェア分解で 1 系列 1 コール×18）。値・fail-closed は lookup_statistic と同一（系列ごとに errors＝unknown_series 等・他の系列は返す）。id_pattern＋dims は find_statistics の families から直接渡せる（登録済みの組合せだけ展開・誤 slug は errors）。上限＝系列 200・値 2,500（超過は range_too_wide と該当数＝黙って切らない）。応答＝values {series_id: {period: value}}・series（title/unit/source{ref（＋表と異なるときだけ citation/vintage/retrieved_at）}/quality＝quality_groups のキー/sample）・sources（表ごとの共通部分＝citation_template・vintage・retrieved_at を含む）・quality_groups（同じ品質メタの系列を 1 定義に）・breaks_catalog・quality_summary（caution／notice の系列一覧・breaks_by_period・usable_from_max・sample_caution）。`verbose=false` で series を省略（units・quality_of のみ）。展開 0 件のときは errors（誤 slug）と coverage（その measure の収録済み組合せ）を返す（第 7 弾 段 A・2026-08-22）。
- **scope**（2026-08-23）：全系列に `scope`＝`jp`（日本の統計＝全国・都道府県）／`intl`（国際比較＝国別 ISO3・IMF/OECD/世銀）。`region_level == "cty"` で機械的に決まる（別フラグを持たない＝矛盾しない）。
  `find_statistics`／`list_datasets` は `scope` で絞れ、指定なしの並びは同順位なら **jp が先**（国際比較は明示的に求められたときだけ、という利用実態に合わせる）。
  sector「対外・国際」は別物（日銀 国際収支など**日本の**対外統計を含む）＝国際比較の判別には scope を使う。
- `find_statistics` の query は**空白区切りの語の AND**（2026-08-22）。0 件のとき `matched_tokens`（語ごとの単独該当数）と hint を返す＝「語を減らせば当たる 0」と「本当に無い 0」を区別できる。`list_datasets` の measures／units は全件（切り捨てない）。`lookup_statistic` の unknown_series は measure が収録済みなら `coverage`（収録済みの業種×規模の組合せ）を返す。
- `list_datasets(sector?, org?)`：**目録**（dataset 単位の集約＝統計名・部門・系列数・粒度・提供期間・地域粒度・単位・タグ・代表 series_id）。「どんなデータがあるか」の入口。`find_statistics(dataset=…)` で掘る導線（2026-08-18 追加）。
- `list_sources()`：org ごとの取得元・最終取得日・件数。
- ツール説明文に「返すもの／返さないもの」を明記（近似・補間・派生計算はしない／推計値は kind で区別／範囲外は ない）。

## 9. 原典完全一致の評価セット（`stats/data/eval/`）

形：`exact_match.jsonl`（正例）と `fail_closed.jsonl`（負例）。git 追跡（正典・小データ）。

正例 1 行：
```json
{"id": "hojin-cash-fy2024", "series_id": "mof.hojin.cash_deposits.allexfin-allsize.fy", "period": "FY2024", "region": "JP",
 "expected_value": "<原典の表示どおりの文字列>", "unit": "百万円",
 "source_locator": {"type": "estat", "statsDataId": "0003060791", "cdCat01": "002", "cdCat02": "104", "cdCat03": "26", "cdTime": "20240"},
 "source_url": "https://www.e-stat.go.jp/dbview?sid=0003060791", "vintage": "2025-09-01",
 "checked_by": "human", "checked_at": "2026-08-xx", "note": "e-Stat 画面で目視確認"}
```
- 作り方：**S 系列ごとに最低 3 点**（最新値・中間の1点・提供範囲の端）を、取込パイプラインとは独立に人手（原典の画面/ファイル）で転記する。合計 ≈ 80–100 点。
- 判定：`lookup_statistic` の `value` が `expected_value` と**文字列として一致**（数値化しない）。かつ `source.accessor` が `source_locator` と一致。
- 負例（fail-closed）：`{"series_id","period","region","expect":"not_found","reason":"…"}`。種類＝範囲外の年（未来・提供開始前）／表記違い（年度系列に暦年）／無い地域／派生値の直接要求／基準改定前の年を新基準系列で要求。**各理由で最低 2 点**。
- 版の追随：取込のたびに正例を再判定し、原典の改定で不一致になった点は「原典を再確認して expected を更新」（自動更新はしない＝人手ゲート）。
- ゲート：`python -m stats.eval.exact_match`（新設）を `mcp_smoke` と並ぶゲートにする（`共通契約.md` §4）。

## 11. 判断が要る点（選択肢と推奨）

1. **値の型**：(a) 文字列保持（推奨・完全一致の定義が明快）／(b) Decimal。
2. **version 指定の lookup**：(a) 最小版では最新版のみ（推奨）／(b) `vintage` 引数を持つ。
3. **派生値**：(a) 仮想エントリ＋構成系列を返す（推奨）／(b) 分配率・GDP比だけは計算して返す（定義を刻めば可だが「原典完全一致」の外に出る）。
4. **projection の返し方**：(a) 同じ lookup で `kind` 明示（推奨）／(b) 別ツール `lookup_projection`。
5. **評価セットの規模**：S 25 系列×3 点＋負例 ≈ 100 点で開始（推奨）。

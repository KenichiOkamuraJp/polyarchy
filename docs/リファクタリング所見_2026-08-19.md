## 冗長性（コピーの堆積）＝段階的リファクタの対象

**claims**
- `ingest/collect.py`（876 行）：5 団体アダプタが同一骨格を 60〜80 行ずつコピー（約 350 行重複）。catalog 行の dict が 5 箇所。→ `fetch_and_record()` 1 本に。ゲート非依存でリスク極小。
- 団体リストが **8 箇所**（`multiquery`・`multistage`・`mcp_server`×2・`app`・`chat_app`・`eval`×2・`evalset_gate`・`qdrant_ingest`）。→ `core/orgs.py` に 1 表。
- eval 採点ヘルパ（`org_of`/`expected_sources`/`normalize`）が `eval.py`・`multistage_eval.py`・`evalset_gate.py` に三重コピー＝片方だけ直すと数値が静かに乖離。→ `eval/_scoring.py`。
- `eval/eval.py`（795 行）＝生成込み eval・検索のみ・フィルタ＋層ゲートの 3 プログラム同居。②③は `search_api.search()` を再実装（ゲートが本番経路を測っていない）。→ 3 分割（機械的移動）→ 本番経路へ寄せる（数値が動きうるので別コミット）。
- `serving/query.py` は Chroma 専用で本線では起動不能なのに `SYSTEM_PROMPT` 1 定数のために `eval.py`・`app.py` が import（chromadb が常にロード）。→ `core/prompts.py` へ。
- 本線から到達しないファイル 10 本（`eval/retrieval_only.py` は上位互換済みで名前も紛らわしい）＋ `scratchpad/` 25 本中 16 本が旧 `src.*` import で実行不能＋ `.bak` 群・`data/chroma` 2.9GB。→ 退避／削除。
- `QDRANT_URL` が 2 箇所定義・`policy_tagger.py:35` が config と異なる既定値を独自に読む。

**stats**
- ingest 10 モジュールに CLI 定型（8 本）・HTTP 取得（7 実装・UA/retry/キャッシュ方針がバラバラ。ESRI だけ UA なし）・`Last-Modified`→published_at（2 箇所同文）・重複値チェック（4 本あり 3 本なし＝捏造防止の網が不均一）・和暦変換（3 実装）がコピー。共通化で **約 450〜500 行（16〜18%）削減**。`boj_file.py` が `esri.py` の私的関数 `_norm`/`cell_text` に依存。→ `ingest/_base.py`（取得・キャッシュ・数値判定・重複検査・CLI・書き出し）。**表の読み方そのものは共通化しない**（原典固有・「1 行/1 列に確定」の要石を緩めない）。

## 段 5-1 の決定（2026-08-19）：eval を本番経路へ寄せる＝**C2 同期の再ベースラインと同時に実施**

試算（commit 99d31cc の `--via-service`）：`PolicySearchService` 経由でも diversify=False なら **86.0%／0.712 に完全一致**。diversify=True（MCP／chat_app の既定）なら **87.4%／0.718**（非劣化・5 問が繰り上がり）。`--filter-eval` の f08（機密層を指定して空を期待）はサービス API に layer 引数が無く表現不能（25/26）。

決定：
1. ゲートは**利用者が実際に見る経路＝`PolicySearchService`＋diversify=True** を測る。新アンカー＝hit@5 87.4%／MRR 0.718（`--eval-set both`）。
2. f08 は `--filter-eval` から外し、層の排他は層ゲート自己検証＋`mcp_layer_gate_test` に一本化（25/25）。
3. `retrieval.py`／`filters.py` の retriever＋reranker 直組みは削除し service 一本化（層ゲート自己検証だけ retriever 直叩きを残す）。
4. **実施時期＝C2 同期（箱の v7/Qdrant 化・再測定イベント）と同時に 1 回だけ**＝長期開発計画 §7「再測定は 2 回に集約」に従う。それまで既定は従来のまま（`--via-service --service-diversify` で随時比較可）。
5. 実施時は ルート README「品質の担保」の基準値・deploy/README §6 の数値を同時に更新。

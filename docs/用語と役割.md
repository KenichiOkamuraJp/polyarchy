# 用語と役割（文書共通の定義）

> **状態：正典（定義はここだけ・他文書は本書へリンクし写さない）。** 起案 2026-09-03・2026-09-04 改訂（全部公開前提・開発者 2 種）・2026-09-19 改訂（公開リポジトリ向けに、特定の当事者間の契約・担い手の記述を除いた）。
> 役割は**人に付く作業上の役割**であり、同じ人が複数を兼ねることはある（兼務の可否は 1c）。誰がどの役割を担うかは、運用する団体が決める。

## 1. 役割

### 1a. 主体

| 主体 | 定義 | 権限 |
|---|---|---|
| **導入団体** | 本ソフトウェアを自組織の名義・環境（AWS・Cloudflare・IdP・GitHub 組織）で運用する団体 | 全リソースの名義と全権。アクセス権の付与・剥奪。運用の継続／縮退の判断 |
| **上流** | 公開リポジトリとその保守者（§3） | 導入団体の運用に役割を持たない。利用条件は LICENSE（Apache-2.0）だけ |

### 1b. 導入団体側の作業役割

| 役割 | 何をする | 要件 | 権限・経路 |
|---|---|---|---|
| **PdM**（プロダクトマネージャー） | **問を決める**＝評価問の採否・意味の判断（年度／暦年・名目／実質 等）・収録の優先順位。**配布の承認**＝main へのマージ権。運用の継続／縮退の判断材料を出す | **Claude Code に適切に指示を出せること**＋ドメイン知識。**プログラミング能力は要件ではない** | GitHub main のマージ権（ブランチ保護＝必須チェック＋承認者）・評価セットの改定・アンカー更新 |
| **開発者**（＝提案者） | **PR を書く**＝Claude Code で変更を作り、ゲートを緑にする。定型拡充（系列追加・期間延長）から新種の収録（計画＋評価問＋実装を 1 つの PR）まで、**作りたい人が提案する**。層による分業はない | Claude Code に指示を出せること。プログラミング能力は要件ではない | PR の作成・自分の PR のゲート結果の閲覧。**マージ権は無い**（承認は PdM） |
| **運用者** | **更新サイクルを回す**＝更新の PR（新着取込・改定反映）を起こしマージまで運ぶ・ダッシュボードの確認・週次トリアージの草稿生成＝**ゲートが検出できる失敗の範囲** | 手順書どおりに動けること | S3 `data/`・`release/`・`code/` の書込＋`ops/` 読取のみ（[deploy/iam-data-operator-policy.json](../deploy/iam-data-operator-policy.json)。CI 化後は CI ロールに移る）。箱には触れない。非開発者が担うための条件＝[運用設計.md](運用設計.md) §0 |
| **障害対応者** | アラームが鳴ったとき箱へ入って手順書で復旧する | 手順書どおりに動けること | SSM Session／Run Command・EC2・CloudWatch Logs |
| **監査人** | 全リソースを読取専用で独立に検証する。コード・文書・品質検査は公開リポジトリと CI で**誰でも**再現できる | — | AWS `ReadOnlyAccess`・公開リポジトリ・CI の履歴・（任意）自身の Claude Code。**PdM とは別人**が担う |
| **利用者** | 自分の Claude／ChatGPT から本サービスを検索・参照する | Claude／ChatGPT の有料プラン | ログイン（外部 IdP）＋秘密パス付き URL（導入団体が認めた人） |

境界の原理＝**品質ゲートが検出できる失敗は開発者・運用者／意味の取り違え（年度/暦年・名目/実質 等）は PdM**（[運用設計.md](運用設計.md) §0）。

### 1c. 兼務の可否

| 組合せ | 可否 | 理由 |
|---|---|---|
| PdM ＋ 運用者 | 可 | 更新 PR のマージは PdM の承認そのもの |
| PdM ＋ 開発者 | 可。ただし**自分の PR は自分で承認しない**（ブランチ保護で強制） | 承認の独立 |
| PdM ＋ 監査人 | **不可** | 監査の独立 |
| 開発者 ＋ 障害対応者 | 可 | — |

## 2. 提供の形

| 記号 | 形 | 内容 |
|---|---|---|
| ① | 試行（PoC） | 少人数・短期間の試行 |
| ② | 導入団体での運用 | 導入団体の名義・環境で稼働・利用者はログイン必須・名簿限定 |
| ③ | 運営者による個人向け提供 | 運営者の自前環境・導入団体とは別テナント・利用規約は公開ページ |

それぞれの進捗は [残タスク](残タスク.md)。

（運用設計 §0 の「層①〜⑥」＝監視／更新／定型拡充／新種の収録／燃料サイクル／再構築 は別の番号。混同を避けるため更新の周回は「更新サイクル（層②）」と呼ぶ。）

## 3. 用語

| 語 | 意味 |
|---|---|
| **箱** | サービスが動く EC2 インスタンス（1 台・SSH なし・入口は Cloudflare Tunnel） |
| **燃料** | 実利用ログ（捕捉ログ＝ツール名・引数・件数・時刻・利用者ハッシュ。会話本文は含まない）。改善の材料。**30 日で自動削除** |
| **昇華資産** | 燃料から、個人・団体を識別できない形に直して評価セット等へ転記した検索文言・評価問・注記。恒久保持・公開リポジトリ内＝誰でも使える。導入団体の協力は任意 |
| **ゲート** | 品質検査＝検索精度と参照の回帰テスト（recommendations 4＋stats 4＋共通 1＝9 本）。**全 PASS のときだけ配布**（fail-closed） |
| **smoke** | 起動直後の疎通試験（箱上で自動適用のたびに実行） |
| **更新サイクル（層②）** | 取込 → ゲート → S3 配布 → 箱の自動適用（失敗時は旧版へ自動切り戻し）の 1 周 |
| **マニフェスト** | `release/data.json`＝出荷時のゲート数値・版・日時を刻んだ配布の証拠。箱はこれにだけ反応する |
| **ダッシュボード** | S3 `ops/dashboard/index.html`（毎時）＝①稼働 ②バージョン・規模 ③データ鮮度 ④利用 の 4 区画 |
| **三点一致** | 認証（案 B）の設定＝IdP の Resource indicator・env の `AUTH_AUD_*`・実 URL（ホスト＋秘密パス）が同一文字列であること |
| **PRM** | Protected Resource Metadata（`/.well-known/oauth-protected-resource`）＝認証サーバの所在を配る固定パス |
| **staging／prod** | staging＝開発者の検証環境／prod＝導入団体の本番環境（`*.<導入団体ドメイン>`） |
| **上流（upstream）** | 公開リポジトリとその保守者。導入団体は自らの GitHub 組織に複製して運用する。上流の更新を取り込むか、導入団体側の改変を上流へ返すかは、どちらも導入団体の任意 |
| **CI** | 公開リポジトリ上で PR／main ごとにゲートを自動実行する仕組み（GitHub Actions）。計画＝運用設計 §2.5。CI 化後の運用者の仕事＝PR をマージ |
| **卒業判定** | 自分で計画と評価問を書き、新種の収録（新モジュール）の PR をゲート全通過で通せること。**到達した人は誰でも PdM に昇格**（複数可・運用設計 §0） |
| **運営者** | ③の形で、自らの環境でサービスを提供する者（公開ページの運営者表記）。導入団体の運用とは無関係 |
| **PdM** | プロダクトマネージャー＝問を決め、配布を承認する役割（§1b）。プログラミング能力は要件でない |
| **アンカー** | recommendations の検索精度の基準値（hit@5／MRR）。回帰を検知するための固定点であって、最大化する目標ではない。値の正典はルート README「品質の担保」 |
| **層（layer）** | 文書の公開区分。本ソフトウェアは**公開層に固定**（ツールに `layer` 引数は無い）。コードやコメントに残る「機密層」は、公開層しか検索経路に出さないことを検査するための概念 |
| **案 A／案 B** | 利用者認証の方式。案 A＝Cloudflare Access の OAuth（2026-09-02 に不採用・スクリプトは温存）／案 B＝外部 IdP による個人認証（現行＝[個人認証_案B設計.md](個人認証_案B設計.md)） |
| **弾／便／段** | 収録拡充の作業単位。弾＝1 つの拡充計画（例：第 9 弾）／便＝弾の中の 1 回の出荷／段＝弾や移行の中の工程（段 0、段 1…）。バッチ 1・2 は、再ベースラインを伴う変更を 2 回にまとめた計画（[長期開発計画](長期開発計画.md) §7） |
| **Phase ○／v5・v6・v7** | 初期開発の工程番号と、recommendations の索引の世代（現行＝v7。コレクション名 `policy_claims_v7`）。当時の設計文書は公開リポジトリに含めていないので、番号は経緯の目印として読む |
| **タスク番号（A1・B17・C6…）** | [残タスク.md](残タスク.md) の行番号。A＝条件待ち／B＝いつでもできる／C＝公開・配布の基盤／D＝長期。詳細な経緯は同書 §E |
| **S-／D-／F-／M の番号** | stats の欠陥番号（S-1…）と、利用側プロジェクトからの要望番号（D-1…・F-1…・M1…）。定義は [stats/docs/データ拡充計画.md](../stats/docs/データ拡充計画.md) の各節 |
| **利用側プロジェクト** | 開発者が本サービスを実務で使って検証している別のプロジェクト（ドッグフーディング）。その文書は公開リポジトリに含めていない |
| **stats-dev／mcp-dev／qdrant-dev** | 開発用の呼び名。stats-dev・mcp-dev＝開発者の PC で動かしていた開発用サーバとそのトンネル（2026-09-02 廃止）／qdrant-dev＝ローカルの Qdrant コンテナ。公開サービスや公式コネクタではない |
| **PP** | プライバシーポリシー（公開ページ `/privacy`） |

## 0. 結論（要点 8 つ）

| # | 要件 | Polyarchy の現状 | 差分 |
|---|---|---|---|
| 1 | **ディレクトリ提出は Team / Enterprise 組織の admin settings 内の提出ポータル**からのみ（個人 Pro/Max では不可・Owner 権限） | 個人アカウント | **Team 組織が要る**（提出者＝組織 Owner。Team は 2〜5 席の最小・$25/席/月前後＝公式価格ページで要再確認） |
| 2 | **カスタムコネクタ（URL 直接指定）は全プランで可**・ディレクトリ掲載とランタイムは同一（違いは審査・発見性・配布・Anthropic 保管クレデンシャル） | claims は authless で運用中 | 掲載前でも「インストールリンク」で配布可 ⇒ ローカル検証・限定配布はこの経路 |
| 3 | 転送は **Streamable HTTP（https）**。SSE は新規非推奨 | `serve_streamable_http`（stateless） | なし |
| 4 | 認証は `oauth_dcr` / `oauth_cimd`（標準対応）・`oauth_anthropic_creds`（要メール）・`static_headers`（β）・`none`。**PKCE S256 必須**・`/token` は form-urlencoded・リフレッシュトークンはローテーション・callback＝`https://claude.ai/api/mcp/auth_callback`（Claude Code は loopback ポート可変） | 認証なし（＋Access JWT 検証の保険は実装済） | **利用者単位 OAuth の導入**（別紙で基盤選定） |
| 5 | **ツール注釈必須**：全ツールに `title`＋`readOnlyHint`（読取）または `destructiveHint`。名前 ≤64 字。説明は「何をするか・いつ呼ぶか」だけ（振る舞い指示・他ツール干渉・宣伝は却下） | `@mcp.tool()` に title/annotations なし | **stats 4 ツール・claims 2 ツールに付与**（FastMCP 1.28: `@mcp.tool(title=…, annotations=ToolAnnotations(readOnlyHint=True))`） |
| 6 | **公開文書**：プライバシーポリシー URL・ドキュメント URL・サポート連絡先・会社名/サイト・アイコン・**利用例プロンプト 3 つ以上**・テストアカウント（審査員が全ツールを叩ける手順） | README は GitHub Private | **公開ページを用意**（置き場は別紙で決定） |
| 7 | **接続元 IP は Anthropic `160.79.104.0/21`**。OAuth の discovery（`/.well-known/*`）・token endpoint も同レンジから来る＝**認可サーバの前段 WAF も同じ許可が要る**。応答期限：discovery/登録/token 10 秒・refresh 30 秒 | `cloudflare-guard.sh connector` で許可済（MCP ホストのみ） | 認可サーバのホストにも同じ許可 |
| 8 | ポリシー：会話データの余分な収集禁止・Claude のメモリ/履歴/ファイル参照禁止・広告/スポンサー禁止・金融取引禁止・**自社 API か正当にプロキシする API**・第三者 IP 侵害禁止・**Terms（規約）と Policy への同意＋免責**（Anthropic を hold harmless） | 検索専用・公開データ・捕捉ログは質問文のみ | 捕捉ログ（燃料）の**扱いをプライバシーポリシーに明記**（何を・何日・何のため） |

**有償化について**：ディレクトリの Terms/Policy に**開発者側の課金を禁じる条項はない**（金融取引・広告・スポンサーが禁止対象）。
課金は自前（Stripe 等）で行い、コネクタは「認証で利用者を識別し、契約者だけに通す」形になる（別紙）。

## 1. 提出ポータルで聞かれること（＝準備物チェックリスト）

提出手順（公式）: Introduction → Connection → Tools → Listing → Use cases → Company → Authentication → Data handling → Test & launch → Compliance → Review

| 段 | 入力 | 準備 |
|---|---|---|
| Connection | サーバ URL（https）・転送（Streamable HTTP）・全利用者が同一 URL か | `https://stats.<domain>/<path>`（秘密パスは公開時に外す＝ディレクトリは URL 公開が前提） |
| Tools | 接続先からツール/プロンプト/リソースを自動同期。**title・注釈欠落はここでフラグ** | 注釈付与（§0 #5） |
| Listing | 名前 ≤100・タグライン ≤55・説明 ≤2,000・カテゴリ 1〜5・**ドキュメント URL・プライバシーポリシー URL・サポート連絡先**・アイコン・スラッグ（永続） | 公開ページ 3 種（Terms/Privacy/Docs）＋アイコン |
| Use cases | 主用途・利用前提（アカウント/プラン）・読取/書込 | 読取のみ。利用例プロンプト 3+ |
| Company | 会社名・サイト・連絡先 | 個人事業/屋号でも可（要 Team 組織） |
| Authentication | `oauth_dcr` / `oauth_cimd` / `oauth_anthropic_creds` / `custom_connection` / `none`。認証なしで開始し一部ツールで要求（lazy auth）も申告可 | 別紙で決定 |
| Data handling | 基盤 API が自社か・許諾を得た提携先か・第三者か／健康データ／スポンサー | 「自社 DB（公的統計を各取得元規約の下で整備）」。第三者データの権利は `stats/docs/再配布条件.md` |
| Test & launch | **審査員がエンドツーエンドで使えるテストアカウント手順**（全リンク・資格情報・手順）。全ツールを MCP Inspector かカスタムコネクタで自分で叩いた確認 | OAuth ありなら審査員用ログイン手段（別紙：Access なら審査員メールを許可） |
| Compliance | 7 つの同意（ガイドライン・第一者 API・金融取引・AI メディア生成・プロンプトインジェクション・会話データ収集・公開ドキュメント） | 全て該当なし／遵守で同意可 |

審査：自動スキャン → 既定で **Community** 掲載。有用と判定されると **Verified** 審査（全ツール機能テスト）に自動昇格。
連絡先 `mcp-review@anthropic.com`。掲載後はダッシュボードでヘルス・利用指標。

## 2. リモート MCP の技術要件（実装に効くもの）

### 2.1 転送・ネットワーク
- Streamable HTTP（stateless で可）・https 必須・**Anthropic 送信元 `160.79.104.0/21`**。
- IP 許可・秘密パス（現行）はカスタムコネクタ配布では有効。**ディレクトリ掲載時は URL が公開になる**ので秘密パスは意味を失う ⇒ 認証（OAuth）と レート制限で守る。
- 応答が遅いと接続失敗扱い（OAuth 各エンドポイント 10 秒・refresh 30 秒）。

### 2.2 認証（OAuth 2.1・MCP 認可仕様）
- 未認証には **HTTP 401 ＋ `WWW-Authenticate: Bearer resource_metadata="https://…/.well-known/oauth-protected-resource[/<path>]"`**（200 の isError ではダメ）。`scope=` を付ければ要求スコープを制御。
- **Protected Resource Metadata（RFC 9728）**：`resource` は利用者が入力する MCP URL と**パスまで完全一致**・`authorization_servers` は最初の 1 件だけ使われる。
- 認可サーバは **RFC 8414 メタデータ**を `/.well-known/` で公開・`code_challenge_methods_supported: ["S256"]`・DCR なら `registration_endpoint`・CIMD なら `client_id_metadata_document_supported: true` ＋ `token_endpoint_auth_methods_supported` に `"none"`。
- 高トラフィックが見込まれるなら **CIMD か `oauth_anthropic_creds` を DCR より推奨**（DCR は接続ごとに新クライアント登録が増える）。
- callback：hosted Claude＝`https://claude.ai/api/mcp/auth_callback`／Claude Code＝`http://localhost/callback`・`http://127.0.0.1/callback`（ポート無視で照合）。
- refresh：401 で反応的に refresh・失効は `invalid_grant`・公開クライアントはローテーション。`offline_access` を `scopes_supported` に載せると refresh token を取りに来る。
- **Lazy auth**（公開ツールは無認証・特定ツールで 401 → Connect カード）も正式サポート。stats は「発見層は無料・参照層は要ログイン」に使える構造。
- 純粋な machine-to-machine（client_credentials）は不可＝必ず利用者の同意画面がある。
- カスタムコネクタでは利用者/管理者が **自前の client_id（＋secret）** を入れて DCR を回避可（組織単位のクライアント）。

### 2.3 ツール設計（審査基準）
- 読取と書込は別ツール（Polyarchy は読取のみ＝該当なし）。`title`＋`readOnlyHint: true`。名前 ≤64 字。
- 説明は「何をするか・いつ使うか」だけ。**外部ツール呼び出し指示・他ツール干渉・振る舞い指示・宣伝は却下**（現在の説明文にある「fail-closed の意味」「値は lookup で」等の**利用手順は可**だが、「利用者 Claude はこう振る舞え」調の記述は点検対象）。
- 有効な引数で必ず成功応答・入力検証と行動可能なエラー文・応答サイズ適正・会話データを余分に集めない。
- MCP Inspector と カスタムコネクタで全ツールを叩いてから提出。

### 2.4 公開文書（Listing で URL を求められる）
| 文書 | 必須 | 中身の要件（Policy） |
|---|---|---|
| プライバシーポリシー | **必須**（不備は即却下） | 収集するデータ・利用と保存・第三者共有・保持期間・連絡先。Polyarchy＝**捕捉ログ（質問文・ツール引数・found 可否・時刻）を 30 日保持し検索品質改善に使う／会話本文は取得しない／利用者識別子（OAuth のメール等）の扱い** |
| ドキュメント | 必須（公開日まで。ブログ/ヘルプ記事で可） | セットアップ・使い方・トラブルシュート・**利用例プロンプト 3 つ以上**・e-Stat API クレジット文の掲出場所にも兼用 |
| サポート連絡先 | 必須 | メール（脆弱性報告の窓口も Terms で求められる） |
| 利用規約（Terms of Service） | ポータル必須項目ではないが**有償化・免責のために自前で必要** | 提供範囲・保証しないこと（fail-closed・値の保証は原典）・料金・解約・第三者データの条件継承（IMF 条項④「無償で IMF から入手可能」の周知など） |

## 3. Polyarchy への含意（何を変えるか＝作業リスト）

1. **組織**：ディレクトリ提出のため Claude **Team 組織**（Owner）が要る。個人配布（カスタムコネクタ＋インストールリンク `https://claude.ai/customize/connectors?modal=add-custom-connector&connectorName=…&connectorUrl=…`）は今のままでも可。**提出時期の判断はユーザー**。
2. **認証**：利用者単位 OAuth（DCR/CIMD）＋利用者 ID をトークンから取れること → 別紙で基盤選定。
3. **注釈**：stats `list_datasets`／`find_statistics`／`lookup_statistic`／`list_sources`、claims `search_policy_docs`／`list_orgs` に `title`＋`readOnlyHint=True`（claims 側は claims セッションで）。
4. **公開ページ**：Terms・Privacy・Docs（＋e-Stat クレジット）を `https://<domain>/…` に静的配置（置き場は別紙）。
5. **入口ガード**：認可サーバのホストにも Anthropic レンジ許可。ディレクトリ掲載時は秘密パス廃止（OAuth に置換）。レート制限は継続。
6. **審査用テストアカウント**：OAuth 化後、審査員がログインできる手段（別紙）。
7. **メタデータ**：`FastMCP(..., instructions=…)`・サーバ名・説明の 2,000 字・アイコン・利用例 3 つ。

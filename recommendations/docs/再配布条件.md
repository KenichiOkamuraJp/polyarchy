# recommendations の再配布・引用の立脚点（発行体別条件と法的根拠）

> **状態：設計（安定リファレンス。発行体の規約・法解釈の確認結果が変わったら更新）。**

版: 2026-08-21／分類: **設計**（安定リファレンス。発行体の規約・法解釈の確認結果が変わったら更新）
位置づけ: `stats/docs/再配布条件.md` の recommendations 版＝公式コネクタ化や、有償で提供する場合の前提整理（残タスク C5）。
凡例: ◎＝出典明示で再配布・商用可／△＝規約上の明示許諾なし or 商用は要相談（**注: recommendations では △ は guide 化を意味しない**＝§4）。

## 0. stats と立脚点が違う理由

stats が扱うのは**数値**（数値データそのものは著作物ではない＝取得元規約のグレードが判定のほぼ全て）。
recommendations が扱うのは**文章**（提言・意見書＝著作物そのもの）。したがって規約グレードだけでは立脚点にならず、
**「どういう形で返すか」が著作権法の権利制限規定の枠に収まっていること**が本体になる。
返す形が枠内に収まる限り、発行体の個別許諾がなくても適法に運用できる——これが recommendations の立脚点。

## 1. recommendations が返す形（実装の契約値＝軽微利用に留まる設計）

| 契約値 | 実装 | 意味 |
|---|---|---|
| 本文は**抜粋のみ・1 チャンク 1,200 字上限** | `core/search_api.py` `text_chars=1200`（MCP・チャットとも。超過は「…」で切断を明示） | 全文を返さない。チャンク自体も取込時 `CHUNK_SIZE=800` で分割済み |
| 返却は **1 応答に上限あり**（search＝既定 5・上限 20 件／sweep＝上限 15 件） | `serving/mcp_server.py` `TOP_K_MAX=20` へ明示クランプ（超過指定は applied_filter に明示）・sweep は per_org≤5×5 団体・15 件上限（2026-08-28 バッチ2 段2 で top_k 上限 5→20・sweep_policy_docs 追加。上限値は変わったが「無制限にしない・超過は開示」の設計は不変） | 大量取得をさせない |
| **ページング・オフセット引数なし** | `search_policy_docs(query, orgs?, since?, until?, field?, top_k?, diversify?)`・`sweep_policy_docs(query, mode?, orgs?, per_org?, since?, until?, field?)` のみ | 「n 件目以降をくれ」ができない＝機械的に全文を復元する経路を提供しない |
| **文書単位の重複抑制**（diversify 既定 on） | 同一文書は最良チャンク 1 件だけ・残数は `same_doc_hits` の数字のみ | 1 文書からの取得量をさらに絞る |
| **全件に出典と原文 URL** | 各ヒットに org・title・date・source_url・page | 所在検索＝原典へ誘導する性格。利用側の適正引用（出所明示）を機械的に支える |
| 公開層のみ・fail-closed | 層は公開固定（`polyarchy_common.metadata_core`） | 非公開文書は構造的に返らない |

取込側（クロール→チャンク→埋め込み→索引）は本文の複製を伴うが、検索結果として公衆に提示するのは上記の抜粋だけ。

## 2. 法的根拠（著作権法・2026-08-21 整理）

1. **収集・索引化（内部複製）＝30 条の 4＋47 条の 5 第 2 項**
   - 30 条の 4（情報解析）: 埋め込み生成・BM25 索引など、著作物の表現の享受を目的としない解析のための複製は許諾不要。
   - 47 条の 5 第 2 項: 所在検索サービスの**準備のための収集・記録**も許諾不要（軽微利用の前段整備）。
2. **検索結果の抜粋提供＝47 条の 5 第 1 項 1 号（所在検索サービスの付随的な軽微利用）**
   - 公衆に提供・提示された著作物について、検索結果の提供に**付随して**、必要と認められる限度で**軽微な**利用（抜粋表示）ができる。
   - 軽微性は「利用部分の割合・量・表示の精度等」で判断される＝§1 の契約値（1,200 字・件数上限（search 20／sweep 15）・重複抑制・非ページング）はこの軽微性を担保するための設計。
   - **営利でも適用される**（主体の限定なし）＝有償コネクタ化と両立する。これが「規約グレード △ でも成立する」根拠。
   - ただし書き: 違法アップロードと知りながらの利用は不可（recommendations の収録元は各発行体の公式サイト＝該当しない）。
   - **政令基準**（施行令 7 条の 4・施行規則 4 条の 5）に従う者であることが条件: ①漏えい防止措置 ②法解釈の文書確認・専門家への相談体制 ③問い合わせ窓口の明示 ④ID/パスワード制限や robots.txt 等の収集拒否措置の尊重。対応状況は §5。
3. **利用側（AI の回答・利用者の文書）の引用＝32 条＋48 条（出所明示）**
   - サービスが常に出典・原文 URL を返すため、利用側は公正な慣行に合致した引用（主従関係・明瞭区別・出所明示）を機械的に行える。
4. **帰属・同一性への配慮**: 抜粋は原文のまま（要約・改変して発行体の主張として提示しない）。切断は「…」で明示。org 表示は catalog の帰属に従う。

## 4. 判定のまとめ（stats の「判定のまとめ」に対応）

- **◎ は 28 件（約 1%）だけ・△ が 3,723 件（約 99%）**——stats（◎ 約 97%）と正反対。しかし recommendations は**値の再配布をしない**
  （§1 の抜粋＋所在提供のみ）ため、△ でも 47 条の 5 の枠内で無償・有償とも運用できる、というのが本文書の結論。
- **grade △ は guide 化を意味しない**: stats が経団連を `status=guide`（値を持たない）に落としたのは、**値を丸ごと再配布する形**
  だったから。recommendations の返す形は最初から軽微利用に留まる設計であり、結論が割れてよい（残タスク C5 注記のとおり）。
- 有償で提供する場合の含意: 47 条の 5 は営利適用可＝発行体への許諾申請は法的には必須でない。ただし
  ①軽微性の限界（ごく短い文書では抜粋の占める割合が上がる。`text_chars` は env で引き下げ可能）
  ②解釈リスク（本文書は自前整理＝法的助言ではない）があるため、**有償化前に専門家レビューを 1 回入れる**
  （施行規則の「専門的知識を有する者への相談」体制の充足も兼ねる）。発行体への事前の通知は、提供する者の判断。

## 5. 政令基準（施行令 7 条の 4）への対応状況

| 基準 | 状況 |
|---|---|
| 問い合わせ窓口の明示 | **済**＝公開ページ `terms.html` §9 連絡先（運営者名・メール）。クローラ UA にも連絡先を明記（`ingest/collect.py`） |
| 侵害情報と知ったときの利用停止・削除申出への対応 | **体制あり**＝catalog から当該文書を外し再索引（collect の skip 管理）。申出窓口は上記連絡先 |
| 漏えい防止措置 | **済**＝層の不変条件（公開層のみ配信・fail-closed）・秘密は SSM・S3 versioning |
| ID/パスワード制限・robots.txt 等の収集拒否措置の尊重 | **一部**＝収集は各発行体の公開一覧ページのみ・低頻度・UA 明示。robots.txt の機械遵守は collect.py 未実装＝**要フォロー**（§6） |
| 法解釈の文書確認 | 本文書がその記録。専門家相談は有償化前（§4） |

# 収録拡充計画：政府の AI・デジタル改革の決定文書（gov への追加）

> **状態：設計（実行計画）。** 起案 2026-10-02。
> 持つもの＝対象文書・取得の作法・メタデータ・評価問（案）・実施の手順。持たないもの＝進捗（[残タスク](../../docs/残タスク.md) B26）・品質の基準値（ルート README「品質の担保」）・審議会の会議資料と議事要旨の扱い（審議会議事録DB＝[長期開発計画](../../docs/長期開発計画.md) §9）。
> 現行の実装名・件数は [collect.py](../ingest/collect.py) と `catalog.csv`。本書の評価問は**取込と同じコミットで評価セットへ移す**（それまでゲートには入らない）。

## 1. 目的と範囲

デジタル行財政改革会議は第 14 回（2026-07-07）で「AI・デジタル改革推進会議」への改組を決め、同会議を中心に人工知能戦略本部・規制改革推進会議と AI の法制度・ガイドラインを見直すとした（取りまとめ 2026「Ⅳ．今後の推進に向けて」）。事務局は 2026 年 9 月にデジタル庁へ移管。
現行の `gov` は骨太方針・規制改革推進会議の答申・財政審の建議の 3 系統で、この議論の**決定文書そのもの**は未収録（骨太や答申の中の引用としてだけ当たる）。

[長期開発計画](../../docs/長期開発計画.md) §2・§9 の原理に従い、**決定文書（主張文書）だけ**を本 DB の `gov` に足す。範囲の宣言は変えない（`gov` の取得元が増えるだけ）。

| 入れる | 入れない（行き先） |
|---|---|
| 会議・本部・閣議の**決定文書の本文** | 回ごとの配布資料・議事要旨・議事録・民間議員の提出資料（審議会議事録DB）／概要版・英訳（本文と重複）／法律の条文・新旧対照（範囲外）／課題発掘対話・連絡協議会など実務の報告（見送り） |

## 3. 取得の作法と地雷

- ★ **内閣官房のサイトは UA が curl だと 404 を返す**（2026-10-02 実測。ブラウザ相当の UA なら 200）。`collect.py` の UA（`Mozilla/5.0 (…)`）はそのまま通る。手で確かめるときも curl の既定の UA では「無い」と誤認する。
- ★ **事務局の移管で URL が変わる可能性**（内閣官房→デジタル庁）。`source_url` は取得時の URL・`retrieved_at` は取得日をそのまま記録し、移管後に旧 URL が消えても書き換えない（出典は取得時点の事実）。一覧ページの移転は更新チェックの失敗で気づく＝その時に索引関数の URL を直す。
- 本文 PDF の文字抽出は 9 本とも良好（PyMuPDF で全ページ取得・スキャン PDF なし）。

## 4. メタデータ

- `org=gov`・`org_type=政府`（既存の 3 系統と同じ）。発行体の細分化（会議体別のファセット）は本便では行わない＝[長期開発計画](../../docs/長期開発計画.md) §5 の「メタデータ書き換え＋再取り込み」で別に判断する（評価資産への影響を伴うため）。発行体は `title` と本文で判別できる。
- `doc_type`＝取りまとめ・基本方針・整備計画・基本計画は **方針**（骨太方針と同じ扱い）。
- `policy_tags`・`doc_nature` は既存の取込手順どおり追い判定で付ける（新規収集は追い判定が要る）。
- ファイル名の接頭辞 `gov_dgk_`（デジタル行財政改革会議）・`gov_aiplan_`（人工知能基本計画）。団体の判定はファイル名の先頭（`gov_`）なので、採点・団体別集計は変わらない。

## 7. 実施の手順（1 つの変更＝計画＋評価問＋実装）

1. `collect.py` の `GOV_SOURCES` に 2 系統を足す：`dgk`（内閣官房の一覧ページの「会議決定」節から「本文」リンクだけを採る）・`aiplan`（内閣府の一覧ページから本文 PDF を採り、概要・英訳を除く）。日付は一覧の和暦（`_wareki_to_iso`）から。
2. 収集 → 追い判定 → 増分取込（[RUNBOOK_OPS](../../deploy/RUNBOOK_OPS.md) §5）。
3. §6 の 12 問を `eval_set.json` に移し、ゲートを回す。
   - **既存の正解が押し出されていないか**を必ず見る（骨太方針・規制改革答申にもデジタル行財政改革の記述がある＝新しい文書が既存の gov の問の上位 5 件に割り込み得る）。アンカーが動いたら回帰として受け止め、検索側の調整で戻さない（過適合をしない）。
   - 基準値の行（ルート README「品質の担保」・`release.sh` の既定値）は**同じコミット**で直す。
4. [再配布条件.md](再配布条件.md) の gov の行・[コーパス収録範囲の明示](コーパス収録範囲の明示.md) と `coverage_note`（[coverage.py](../core/coverage.py) の「政府の主要方針文書（骨太方針・規制改革推進会議・財政制度等審議会）のみを収録」＝取得元を列挙している）を同じコミットで更新する。ツールの説明文と serverInstructions の gov の列挙も同様（説明文を変えると ChatGPT のコネクタは作り直し＝運用側へ申し送る）。
5. 配布は運用側のフォルダから（ルート CLAUDE.md §4）。

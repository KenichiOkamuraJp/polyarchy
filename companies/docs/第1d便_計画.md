# 第 1d 便 計画（遡り＝2013 年ごろの決算期まで）

> **状態：設計（2026-09-28 起案）。** §2 は全項目決定（本人・2026-09-28＝§2-1 は毎年の有報を全部・§2-2〜§2-6 は推奨案どおり）。**2026-09-30＝取得・取込・評価問・本番の置き場への差し替えまで済・ゲート全 PASS**（[記録](記録/遡りの取込と棚卸し_2026-09-30.md)）。残＝配布（運営者）・原本 zip の S3 退避（§2-5）。

[開発計画](開発計画.md) §2 の便の表に足す。第 1〜1c 便は各社の**最新の有報 1 本**（2025-06〜2026-09 提出・4,330 書類）だけを取り込んでいる＝決算期は 2021〜2026 年。これを過去へ延ばす。

## 1. 何を作るか

- EDINET API で取れる最古の提出日（約 10 年前＝2026-09-27 に確かめた範囲の端は 2016-09-29 前後）から、いまの収録の手前（2025-06-15）までの**有報をすべて**取り込む。5 期推移の四期前まで入るので、決算期は **2012〜2013 年まで**遡る（3 月決算なら 2017-06 提出の書類の四期前＝2013-03）。
- ツール・引数・返り値の契約は**変えない**。値の置き場はもともと「同じ決算期の値が複数の書類に載る＝全部持ち、既定は提出日が最新の書類の値・`doc_id` で書類を指定できる」形（`core/store.py`）＝書類を足すだけで古い期が引けるようになる。
- セグメント別・地域別（各書類に当期・前期の 2 期）も同じ取込で毎年ぶん入る。横断検索は `period_from`／`period_to` で古い決算期を条件にできる（`_context` がその期を当期とする書類を選ぶ）。

## 2. 決めること

1. **取り込む書類の範囲＝毎年の有報をすべて**（決定・本人 2026-09-28）。会社ごとに数本を拾う案は、横断検索で古い年を条件にできず、セグメント別・地域別が飛び飛びになり、上場廃止した会社が入らない（生存バイアス）ため採らない。訂正有報は今と同じく外す（第 3 便）。
2. **収録範囲の宣言**（決定）＝「2013 年以降」と切らず、**取り込んだ書類に載っている期をそのまま収録**とする（12 月決算の会社は 2017-03 提出の書類で 2012-12 期まで載る）。切り捨ては事実を捨てるだけで得るものが無い。宣言は「EDINET API で取れる最古の書類（提出日で約 10 年前）の 5 期推移まで」とし、収録外の期は今の `out_of_range`（`available_periods` つき）で返す。公開ページ・ツールの説明の収録範囲の 1 行を直す。
3. **上場廃止・吸収された会社**（決定）＝登録簿に入れる（事実）。発見層の返り値に**最新の書類の提出日**（既にある `submitted`）が載ることで「今も提出している会社か」は利用側で判別できる。横断検索は既定（期の指定なし）で今と同じく `stale_period`（基準日から 18 か月より前）として除外される＝いまの問の答えは変わらない。★社名の再使用・似た社名で `find_company` の曖昧さが増える＝`find_quality` を回してから決める（候補を返す既存の契約で足りる見込み）。
4. **箱のメモリ**（決定）＝全量を取り込んだ置き場で `_index()` を測り、1GB を超えるなら索引を細くしてから配布する。細くする候補＝①索引に持つのは語彙の要素と会社の最上段の収益だけ（今も同じ）で、値の組を tuple から共有の文字列表へ ②書類ごとに 5 期を持つのをやめ、横断検索が使う期（当期と式の期のずれの最大）だけにする。**取込・評価は細くする前に進められる**（手元の PC はメモリに余裕がある）。参照層（`lookup_company_facts` 等）は 1 社ずつ読む＝影響は置き場のファイルの大きさだけ（全体で約 1.5〜2GB の見込み・箱のディスクは十分）。
5. **原本の退避**（決定）＝取得した zip（約 30GB）を S3 のデータの原本の置き場へ。API から消えた書類は二度と取れない＝値の置き場を作り直せる根拠はこの zip だけになる。退避は運営者の作業（S3 へのアップロードの許可が要る）。
6. **語彙**（決定）＝古い書類にだけ出る標準要素（上の三菱ＵＦＪの 1 つ 等）は、`population_report` で母集団の全件を洗ってから、公式 CSV でラベルを確かめて足す（今までと同じ＝問を立ててから足す）。語彙に無い要素も値の置き場には持つ（`alternatives` に出る）＝足さなくても事実は失われない。

## 3. 評価問（先に立てる）

期待値は今と同じく**公式 CSV と自前の取込の 2 経路で一致した点だけ**。古い書類の CSV も取れることは確かめ済み。

- **正例**
  - 古い書類にしか載らない期＝各書類の四期前（2013-03 期ならその期は 2017 年提出の書類にしか無い）×業種の様式（日本基準・IFRS・米国基準・銀行・証券・保険・建設・連結なし）×20 社ほど。
  - 遡及修正＝同じ期の値が古い書類と新しい書類で違う会社＝既定は新しい書類の値・`other_documents` に古い書類の値が並ぶ・`doc_id` で古い書類の値が返る。
  - セグメント別・地域別＝古い書類の当期（数社）。
  - 横断検索＝`period_to` で古い期（例＝2016-03 期）を条件にした問＝その期を当期とする書類から計算され、行の出典の書類がその年の書類であること。
  - 発見層＝上場廃止した会社・社名を変えた会社を旧社名で（今も 1 問ある型を古い社名へ）。
- **負例**
  - 取得範囲より前の期（3 月決算の会社の 2012-03）＝`out_of_range`＋`available_periods`・近い期の値を返さない。
  - 上場廃止した会社が、期の指定のない横断検索に出ない（`stale_period` の件数に出る）。
  - 決算期の変更・会計基準の移行年（米国基準→IFRS 等）が古い期で順位に出ず、除外の理由に出る。
  - 収益認識基準の適用（2022 年 3 月期ごろ）で売上高が不連続になる会社＝前年比の上位に黙って出ない（基準の変更として除外されるか、行に出るなら何で判別できるかを実測で確かめてから問にする）。

### 立てた問（2026-09-28・`eval/make_backfill_candidates.py`）

- `backfill.jsonl`（正例 55）・`backfill_fail_closed.jsonl`（負例 12）＝最古の書類の四期前（書類を指定しない参照でもその書類の値）× 様式 12 書類（米国基準・建設・銀行・IFRS〔インスタンス 2 個〕・保険・証券・連結なし・12 月決算・7 月決算）＋最古の書類の当期（書類を指定）＋取得範囲より前の期（`out_of_range`）。遡りの取込が前提＝本番の置き場への取込と同じ変更で git に入れる。
- `period_basis.jsonl`（正例 7）・`period_basis_fail_closed.jsonl`（負例 3）＝連結の有無は決算期ごと（上の表）。
- 既存の `exact_match.jsonl`／`fail_closed.jsonl` は人手で足した問（ソニーの接頭辞なし・E03160 の ROE 等）がある＝`make_candidates` で再生成しない（再生成すると失われることを 2026-09-28 に確かめた）。
- 残り（全量の取得のあと）＝遡及修正（同じ期の値が古い書類と新しい書類で違う）・横断検索の古い期・上場廃止した会社の発見層・証券コードの再使用。

## 4. 手順

1. **取得**（2026-09-28 開始）＝`python -m companies.ingest.edinet --fetch-only --from 2016-09-29 --to 2025-06-15`（古い日から＝消える側から先に取る・1 リクエスト／秒・約 1 日）。
2. 手元の別の置き場（`COMPANIES_STORE=<一時の置き場>`）へ全量を取り込む→ `population_report`・`_index()` のメモリ・取込エラーの型を記録（記録＝`記録/遡りの取込と棚卸し_<日付>.md`）。
3. §3 の評価問を立てる（`make_candidates` 等に古い書類を足す）→ 本番の置き場への取込→ ゲート全 PASS。
4. §2-4 のメモリの手直し（要るなら）→ 公開ページ・ツールの説明の収録範囲の 1 行→ 配布（運営者）→ §2-5 の原本の退避。
5. 日次差分の定常化（第 3 便）までは、新しい提出は今と同じく手で取り込む。

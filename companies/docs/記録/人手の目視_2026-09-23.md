# 人手の目視（有価証券報告書の PDF との照合 10 点・2026-09-23）

> **状態：記録（照合の結果・2026-09-23。更新しない）。**

[開発計画](../開発計画.md) §評価問の「人手の目視（有報の PDF との照合）は未＝最初のゲート PASS のあとに 10 点を抜き取りで行う」の実施。
評価問の期待値は EDINET 公式 CSV と自前のパーサの 2 経路一致で取っているが、どちらも XBRL 由来である。ここでは**人が読む書類（PDF）と、利用者が実際に受け取る値**が一致するかを見る。

- 値の取り方＝staging の公開ホストに接続した companies ツール（`lookup_company_facts`／`find_company`）で引いた。利用者と同じ経路。
- 照合の場所＝各書類の「第一部 第 1 企業の概況 1 主要な経営指標等の推移」（⑨ は「5 従業員の状況」）。書類は表の書類管理番号から開く（`https://disclosure2.edinet-fsa.go.jp/WZEK0040.aspx?<書類管理番号>`）。
- 値の単位＝ツールは円単位の文字列で返す（`decimals` は開示の丸め）。PDF の表の単位（百万円・千円）に直した値を並べた。

## 2. 照合で見ること（値の一致に加えて）

- ⑤⑩＝**同じ決算期の値が書類によって違う**のは遡及修正として正しいか（新しい書類の表に修正の注記があるか）。
- ⑥＝PDF に IFRS の表と日本基準の表が**両方**載っているか。
- ⑦＝PDF の表に「売上高」の行が本当に無く、「経常収益」が最上段か。
- ⑧＝表の単位が千円か（`decimals=-3` と整合するか）。
- ⑨＝「40.5 歳」の形で開示されているか（「40 歳 6 か月」の形なら月の取り漏れ）。

## 3. 照合の前に見つかった不具合（値ではなくラベル）

⑤を引いた時点で、**会社の拡張要素のラベルが空（`label: null`）**だった。契約（[開発計画](../開発計画.md)）では、各社の拡張要素は「会社のラベルつきで別に返す」はずである。値の置き場の全件を数えると、拡張要素 5,492 値のうち **2,490 値（243 社）でラベルが空**だった（ラベルが入っている会社は 289 社）。空のラベルは `alternatives` にも出る。利用側の LLM は要素 ID の英語名からしか意味を推せない。
原因の見当＝取込時にラベルを読む `companies/ingest/edinet.py` の `extension_labels`（ラベルリンクの正規表現）が、一部の書類の書式に合っていない。値そのものは正しく入っているので、目視の判定とは別に直す（評価問＝ラベルが空の拡張要素が 0 件であることを先に立ててから直す）。

## 4. 結果

**10 点すべて○**（2026-09-23・運営者が PDF と照合）。§2 の観点（遡及修正・基準の併記・売上高の行の無さ・千円単位・年齢の表記）も含めて、ツールの返り値と PDF の表は食い違わなかった。
XBRL 由来の 2 経路一致（評価問）に加え、人が読む書類との一致も抜き取りで確かめられた＝第 1 便の値の正しさについて、残っている確認はない。
§3 のラベルの欠落は値の正しさとは別の不具合として、後続で直す（[残タスク B25](../../../docs/残タスク.md)）。
